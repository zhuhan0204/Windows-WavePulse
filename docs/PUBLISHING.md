# 公开发布流程（维护者）

目标仓库：https://github.com/zhuhan0204/Windows-WavePulse

本文件不会自动执行 Git。**只有作者明确要求“上传 Git / GitHub”后，才提交、推送、创建标签与 Release。**

## 当前约定

- 首个公开版本统一为 `v0.1`，不拆分首发前的内部调试版本。
- 本地保留个人耳机适配，公开快照移除个人地址映射。
- 不直接对整个个人开发目录执行 `git add .`。
- 白名单公开源码准备到 `artifacts/github-source-v0.1/`，这里只是待上传目录。
- 公开 EXE 从脱敏源码重新构建，不直接上传旧的个人自用 EXE。
- 附件与校验值准备到 `artifacts/releases/v0.1/`。普通用户通过 Release Assets 下载，不把历代 EXE 混进源码目录。

## 每次更新

1. 确定版本：首版 `0.1` / 标签 `v0.1`，后续例如 `0.2` / `v0.2`。
2. 更新 `VERSION`、工程、原生资源、应用内版本与构建输出名称。当前有固定版本字符串，不能只改 VERSION 就直接发布。
3. 新记录加入 `CHANGELOG.md` 最上方，填写实际发布日期，区分新增 / 优化 / 修复 / 已知问题。
4. 更新 `docs/releases/vX.Y.md`；界面变化则更新示例截图。
5. 阅读并执行本地 `tools/Prepare-PublicRelease.ps1`。它不访问 GitHub，不提交或推送；已有依赖缓存时可加 `-Offline`。脚本拒绝覆盖现有公开快照，应先单独保留旧快照。
6. 运行 `tools/Test-PublicRelease.ps1`，核对公开源码、文档链接、EXE 内置公开主程序、耳机通用标签、ZIP 内容和 SHA-256；另外完成适当的运行测试。
7. 作者明确要求上传后，先检查远端已有内容，保留已有文件与历史，再从公开快照提交，不强制覆盖未知远端历史。
8. 创建对应标签和独立 Release，上传 EXE、ZIP、`SHA256SUMS.txt`，正文使用版本文案。
9. 确认未登录用户能打开 Release 和下载附件，README 截图与版本链接正确。

首版附件：`WavePulse-v0.1-win-x64.exe`、`WavePulse-v0.1-win-x64.zip`、`SHA256SUMS.txt`。GitHub 从标签提供源码归档。后续新建标签和 Release，不静默覆盖旧版附件。

## 上传前检查

- [ ] 上传公开快照，而不是整个自用工作区。
- [ ] 没有个人配置、日志、缓存、凭据、签名证书或真实设备地址。
- [ ] 没有 `.tools/`、`.test/`、`bin/`、`obj/`、旧发布目录与厂商驱动拆包物。
- [ ] 截图无个人设备名、地址、桌面或后台应用，并注明示例数据。
- [ ] EXE 来自公开源码，不含个人配置，校验值一致。
- [ ] 已说明兼容范围、多屏实测限制、充电电量限制与日志隐私。
- [ ] 许可证由作者确认，不擅自添加 MIT / GPL 等授权。
- [ ] 本次上传已有作者明确授权。
